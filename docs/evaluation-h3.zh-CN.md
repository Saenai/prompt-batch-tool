# H3 Prompt 横评标准

本标准用于评价模型把自然语言需求转化为可直接用于 MiniMax H3 的 prompt 时所表现出的任务执行能力与创作能力。它只衡量 prompt-authoring 场景中的代理表现，不外推为通用工具调用或长期规划能力。

## 1. 评价原则

- 对结果匿名化并打乱顺序后评分，完成后再恢复模型与 repeat 信息。
- Agent 能力和创作能力分别采用 5 分制，不允许创意抵消协议失败。
- 只评价最终交付结果，不根据隐藏推理的长度或文风评分。
- 台词语言、人物国籍、trigger、画幅、时长和禁止项必须从每次任务输入中提取，不在评分器中硬编码。
- 国籍与语言是两个独立约束。例如“韩国人说中文”必须同时满足韩国人物设定和中文台词，不能根据国籍擅自改为韩语。
- 更长、镜头更多、形容词更密集不等于更有创造力；短视频 prompt 还应评价克制与可执行性。

## 2. Agent 能力（5 分）

| 子指标 | 权重 | 观察内容 |
|---|---:|---|
| 需求理解与覆盖 | 30% | 主体、动作、场景、风格、台词、语言、镜头及其他要求是否完整落实 |
| 硬约束遵从 | 25% | trigger 是否按任务要求逐字保留；语言、时长、画幅、禁止项等是否准确 |
| H3 格式与协议 | 20% | 字段齐全、顺序正确，无解释前言、Markdown 包装或多余内容 |
| 可执行性 | 15% | 镜头数量、动作密度、空间关系和时间安排是否适合实际视频生成 |
| 信息控制 | 10% | 不擅改关键要求，不制造冲突，不以空泛描述替代明确指令 |

评分锚点：

- 5：完整准确，可直接用于生成，没有实质性修改需求。
- 4：存在轻微遗漏或措辞问题，但不影响执行。
- 3：基本理解正确，需要局部修改才能可靠使用。
- 2：多项约束遗漏、误解，或存在明显执行冲突。
- 1：拒绝、空输出、严重跑题或格式完全不可用。

硬性封顶：

- trigger 被改写、翻译或遗漏：Agent 最高 3 分。
- 台词语言错误或核心情节反转：最高 2.5 分。
- 缺少 H3 必需字段或输出大量前言：最高 2 分。
- 拒绝、空输出或没有最终 prompt：记 0–1 分，并标记不可用。

## 3. 创作能力（5 分）

| 子指标 | 权重 | 观察内容 |
|---|---:|---|
| 概念展开与原创性 | 25% | 是否超越输入复述，形成鲜明但不过度偏离的方案 |
| 视觉导演能力 | 25% | 构图、镜头运动、景别、光线和动作是否具体而有画面感 |
| 叙事与节奏 | 20% | 短时长内是否有清楚的情绪推进与收束 |
| 台词及多语言表达 | 15% | 台词语言是否符合任务，表达是否自然并推动叙事 |
| 声音与视听整合 | 10% | 环境音、动作音、音乐与画面是否互相支持 |
| 克制与聚焦 | 5% | 是否避免镜头过载、形容词堆砌和创意点互相竞争 |

评分锚点：

- 5：鲜明、原创、连贯，而且创意能够被视频模型实际兑现。
- 4：有明显创作价值，少量细节偏常规或略显拥挤。
- 3：合格但较模板化，是可靠的常规方案。
- 2：平淡、堆砌、叙事松散，或创意与要求冲突。
- 1：几乎没有有效创作，或内容不可理解。

## 4. 重复生成与稳定性

稳定性不是第三个主维度，而是分别附着在 Agent 和创作能力上的统计属性。每个 profile 至少报告：

- 均值、中位数、最低分、最高分和极差；
- 可直接使用率、硬约束失误次数和明显低谷次数；
- 重复之间的创意相似程度，以及完全重复或高度同质化情况。

平均分相同的模型，应优先比较最低分和可直接使用率，以区分稳定型与高上限但易失手型。

## 5. 执行流程

1. 从任务输入和 system prompt 提取逐项硬约束清单。
2. 生成匿名样本 ID，并将模型、模式和 repeat 映射单独保存。
3. 第一遍检查硬约束、H3 格式和可执行性。
4. 第二遍在不知道模型身份的情况下评价创作质量。
5. 解盲后按 profile 汇总五次结果，并分别形成 Agent、创作和稳定性结论。
6. 初始报告不强行合并总榜；若需生产推荐，可使用 Agent 60%、创作 40%，并对最低 Agent 分施加风险惩罚。
